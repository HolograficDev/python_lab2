# Почтовые отправления (Postal Service)

Консольное приложение на Python для расчёта стоимости и срока доставки почтовых отправлений: **письма**, **бандероли** и **посылки**. Результаты расчётов сохраняются в базе данных SQLite и могут быть выгружены в отчёты Word (`.docx`) и Excel (`.xlsx`).

Лабораторная работа №2 «Модули и пакеты Python. ООП» по дисциплине «Теория алгоритмов».

- **Вариант:** №6 — «Почтовые отправления»
- **Уровень сложности:** Well-done (Rare + Medium + Well-done)
- **Язык:** Python 3.12+ (в Docker используется 3.12)
- **База данных:** SQLite (`sqlite3`)
- **Контейнеризация:** Docker

## 1. Описание

Приложение моделирует почтовые отправления тремя классами, наследующими абстрактный `PostalItem`. Стоимость доставки зависит от:

- **расстояния** (км);
- **сроков** доставки (стандартная / ускоренная / экспресс);
- **веса** и **объёма** отправления (используется расчётная масса — большая из фактической и объёмной);
- **типа доставки** (до отделения / заказное / курьером до двери);
- особенностей типа отправления (уведомление о вручении, печатная продукция, объявленная ценность, хрупкость).

Приложение также определяет ожидаемый срок и дату доставки, сравнивает все 9 вариантов доставки и находит самый дешёвый и самый быстрый.

## 3. Формулы расчёта

```text
расчётная_масса = max(масса, длина * ширина * высота / делитель)    # для письма объём не учитывается
тариф           = базовый_сбор + расчётная_масса * плата_за_кг + расстояние / 100 * плата_за_100_км
перевозка       = тариф * коэффициент_срочности
доплаты         = доплаты_и_скидки_типа(перевозка)
ИТОГО           = перевозка + доплаты + плата_за_способ_доставки
срок (сутки)    = max(1, ceil(расстояние / скорость_км_в_сутки) + сутки_на_обработку)
```

Каждая составляющая округляется до копеек (правило «половина вверх»).

### Тарифы по типам отправлений

| Параметр | Письмо | Бандероль | Посылка |
|---|---|---|---|
| Базовый сбор, руб. | 30 | 80 | 150 |
| Плата за 1 кг, руб. | 120 | 70 | 50 |
| Плата за 100 км, руб. | 3 | 6 | 9 |
| Делитель объёмной массы, см³/кг | не учитывается | 6000 | 5000 |
| Макс. масса, кг | 0,5 | 5 | 20 |
| Габариты | 35×25×2 см | сторона ≤ 60 см, сумма ≤ 90 см | сторона ≤ 120 см, сумма ≤ 220 см |
| Доплаты / скидки | +25 руб. за уведомление о вручении | −15 % для печатной продукции | +3 % от объявленной ценности; +15 % за хрупкое |

### Срочность и типы доставки

| Срок | Коэффициент | Км/сутки | Суток на обработку |
|---|---|---|---|
| Стандартная | 1,0 | 400 | 2 |
| Ускоренная | 1,5 | 700 | 1 |
| Экспресс | 2,0 | 1000 | 0 |

| Тип доставки | Доплата, руб. |
|---|---|
| До отделения связи | 0 |
| Заказное (под подпись) | 60 |
| Курьером до двери | 250 |

> Тарифы и ограничения учебные, они не совпадают с тарифами реальных почтовых операторов.

**Пример.** Посылка 10 кг, 50×40×30 см (объёмная масса 12 кг), объявленная ценность 5000 руб., хрупкая; 2000 км, экспресс, курьером:
тариф = 150 + 12·50 + 20·9 = 930; перевозка = 930·2 = 1860; доплаты = 150 + 279 = 429; итого = 1860 + 429 + 250 = **2539,00 руб.**, срок 2 суток.

## 4. Объектная модель

- `PostalItem` (ABC) — общие параметры (отправитель, получатель, масса, габариты), расчётная масса; абстрактные `type_code`, `type_name`, `check_limits()`, `calculate_extras()`.
- `Letter`, `Banderol`, `Parcel` — потомки с собственными тарифами, ограничениями и доплатами.
- `Quote` — результат расчёта: составляющие стоимости, срок и дата доставки.
- `DeliverySpeed`, `DeliveryMethod` — справочники (Enum).
- Управляемые атрибуты реализованы через `@property` и сеттеры с проверкой значений.
- У каждого класса определено не менее двух dunder-методов (`__init__`, `__str__`, `__repr__`, `__lt__`).

## 6. Краткая справка

```text
========== ПОЧТОВЫЕ ОТПРАВЛЕНИЯ ==========
1. Создать письмо
2. Создать бандероль
3. Создать посылку
4. Список отправлений
5. Рассчитать стоимость и срок доставки
6. Сравнить все варианты доставки
7. История расчётов и статистика
8. Сохранить отчёт в Word (.docx)
9. Сохранить отчёт в Excel (.xlsx)
0. Выход
```

1. Создайте отправление (пункты 1–3), введите отправителя, получателя, массу (кг) и габариты (см). Дробные числа можно вводить через точку или запятую.
2. Пункт 5: выберите отправление, введите расстояние, срок и тип доставки. Программа покажет состав стоимости, срок и дату доставки и **сохранит результат в БД**.
3. Пункт 6: таблица всех 9 вариантов доставки с отметками «дешевле всего» и «быстрее всего» (в БД не сохраняется).
4. Пункт 7: история сохранённых расчётов и статистика.
5. Пункты 8 и 9: отчёты сохраняются в папку `reports/`.

Файл базы данных: `data/postal.db` (создаётся автоматически; открыть можно в DBeaver или DB Browser for SQLite). Таблицы: `shipments` (отправления) и `quotes` (результаты расчётов, внешний ключ на `shipments`).

## 7. Тесты

```powershell
python -m pytest -v
```

Тесты покрывают справочники, классы отправлений (валидация, ограничения, доплаты), расчёт стоимости и сроков, аналитику, работу с SQLite (в том числе внешние ключи) и экспорт отчётов. Для БД и отчётов используется временный каталог (`tmp_path`), рабочая база не затрагивается.

## 8. Docker

Сборка образа (библиотеки из `requirements.txt` устанавливаются при сборке):

```powershell
docker build -t postal-service .
```

Запуск с сохранением базы в томе Docker и отчётов в папке `reports` на компьютере:

```powershell
docker run --rm -it -v postal-data:/app/data -v "${PWD}/reports:/app/reports" postal-service
```

Запуск тестов в контейнере:

```powershell
docker run --rm postal-service python -m pytest -v
```

После изменения кода образ нужно собрать заново (`docker build -t postal-service .`).
